# NHN Cloud 콘솔 안내 챗봇 — UI 고도화 설계 (2C)

작성일: 2026-09-18. 기반: `2026-09-18-console-guide-bot-production-design.md`(2B) 위에서 동작하는 Streamlit UI(`app/chat_page.py`, `app/admin_page.py`).
사용자가 설계 판단을 위임했다("전부 너 판단대로"). 아래 결정은 모두 컨트롤러의 판단이며, 되돌리기 쉬운 순서로 잘랐다.

## 1. 목적

이 봇의 핵심 가치는 "메뉴 경로 + 스크린샷을 빨리 읽는 것"이다. 2C 는 답변을 읽는 경험을 다듬고(2C-1), 대화를 오가며 쓰는 편의와 운영자의 시각 확인을 더한다(2C-2). 프론트엔드 교체(React 등)는 하지 않는다 — Streamlit 안에서 끝낸다.

## 2. 범위와 순서

| 단계 | 내용 | 산출물 |
|---|---|---|
| 2C-1 답변 읽기 경험 | 진행 표시에 후보 문서 칩, 스크린샷 크게 보기, 인용 번호 + 출처 카드, 다시 생성, 첫 화면 예시 교체 | `chat_page.py`, `rag.py`(프롬프트), `styles.py`, 테스트 |
| 2C-2 대화·관리자 | 세션 내 대화 목록(새 대화/전환/제목), 관리자 일별 추이 그래프·👎 답변 펼치기·질문 검색 | `chat_page.py`, `admin_stats.py`, `admin_page.py`, 테스트 |

두 단계는 브랜치 하나(`feature/phase2c`)·PR 하나. 2C-1 이 끝나면 배포해 눈으로 확인하고 2C-2 로 간다.

## 3. 2C-1 답변 읽기 경험

### 3-1. 진행 표시
- `st.status` 안에 검색이 끝나는 즉시 후보 문서 칩을 그린다: `서비스 · 문서명 › 섹션` 한 줄씩(최대 5개, 리랭킹 전 상위 5). 리랭킹이 끝나면 같은 자리에 최종 5개로 갱신한다.
- 상태 라벨은 `검색 중 → 관련도 평가 중 → 답변 작성 중 · 검색 N초` 로 짧게. 완료 후 status 는 접힌 채로 남긴다(지금과 같음).

### 3-2. 스크린샷 크게 보기
- `render_answer` 의 각 이미지 아래에 작은 버튼 `크게 보기` 를 둔다. 누르면 `@st.dialog("스크린샷", width="large")` 로 같은 파일을 큰 폭으로 보여 준다(캡션 포함).
- 버튼 키는 `zoom_{question_id}_{N}` — 기록을 다시 그릴 때도 같은 키. `question_id` 가 없으면(로그 실패) `zoom_{session_seq}_{N}` 로 대체(세션 카운터).
- 이미지 본문 표시는 지금처럼 컨테이너 폭 기준. 경로 검증·파일 없음 처리는 유지.

### 3-3. 인용 번호와 출처 카드
- 프롬프트: 두 시스템 프롬프트(콘솔·일반) 공통에 "근거로 삼은 문서 번호를 그 문장이나 단계 끝에 `[1]` 처럼 적어라(문서 블록의 번호와 같은 번호, 여러 개면 `[1][3]`)" 를 추가한다. 번호는 `[문서 i]` 의 i 와 같다.
- 답변 본문의 `[n]` 은 그대로 둔다(마크다운 텍스트, HTML 주입 없음).
- 출처는 접힘 expander 대신 답변 바로 아래 **항상 보이는 카드 목록**으로 바꾼다. 카드 한 줄: `[n] 문서명 (서비스) › 섹션 경로 · 원문 ↗`. n 은 프롬프트 순서(= `cands` 순서). 5줄이 넘지 않는다(참고 문서 수 슬라이더 상한 10 → 카드도 그 수만큼).
- `render_sources(cands)` 는 번호를 붙이도록 바꾸고, `questions.sources` 는 그대로(순서가 곧 번호).

### 3-4. 다시 생성
- 답변 하단 👍/👎 옆에 `다시 생성` 버튼. 누르면 같은 질문을 `pending` 에 넣고 rerun — 검색부터 다시 한다. 이전 답변은 기록에 남고 새 답변이 아래에 붙는다(덮어쓰지 않음 — 비교 가능, 로그도 별도 행).

### 3-5. 첫 화면
- 예시 질문 4개를 스크린샷이 있는 서비스로 교체(2B 평가에서 확인): `DNS Plus에서 레코드 세트를 생성하는 방법`, `SMS 발신 번호를 등록하는 절차`, `인스턴스를 생성하는 방법`, `Cloud Monitoring에서 대시보드를 생성하는 방법`.
- 안내 문구 아래에 한 줄 힌트: "서비스 이름을 함께 쓰면 더 정확합니다 (예: VPC, Object Storage)".
- 카테고리 타일은 만들지 않는다(YAGNI).

## 4. 2C-2 대화 관리와 관리자 시각화

### 4-1. 대화 목록 (세션 안)
- `st.session_state.conversations: list[dict(id, title, messages, last_service)]`, `st.session_state.current: id`. 로그인이 없으므로 브라우저 세션 동안만 유지한다(새로고침하면 사라짐 — 첫 화면 힌트에 명시).
- 사이드바 맨 위: `새 대화` 버튼, 그 아래 대화 제목 목록(버튼, 최근 것이 위, 최대 20개). 제목은 첫 질문 앞 24자.
- `대화 초기화` 버튼은 `현재 대화 지우기` 로 이름을 바꾸고 현재 대화만 비운다.
- `questions.session_id` 는 그대로 브라우저 세션 단위(대화 단위가 아님) — 로그 스키마 변경 없음.

### 4-2. 관리자 시각화
- `admin_stats.daily(conn, since) -> list[(date, questions, median_ms, down)]` (일별, `asked_at::date` 기준, 시간대 Asia/Seoul).
- 관리자 페이지 상단 지표 아래에 `st.line_chart` 두 개(일별 질문 수, 일별 응답 중앙값 초)와 👎 일별 막대(`st.bar_chart`).
- 👎 목록의 각 행에 `st.expander` 로 답변 전문(`answer`)과 출처(`sources`)를 펼쳐 볼 수 있게 한다(`recent_down` 이 answer 전문과 sources 를 함께 돌려주도록 컬럼 추가 — 200자 절단 컬럼은 유지).
- 질문 검색: 텍스트 입력 → `admin_stats.search(conn, since, text, limit=50)` (`question ILIKE %text%`), 결과 표(시각·질문·서비스·grounded·feedback).

## 5. 오류 처리
- 크게 보기 다이얼로그에서 파일이 없으면 `st.warning("스크린샷 파일을 찾을 수 없습니다")`.
- 다시 생성은 새 질문과 같은 경로라 별도 처리 없음.
- 대화 전환 중 답변 생성이 진행 중이면(Streamlit 특성상 rerun 으로 끊김) 진행 중이던 답변은 버려진다 — 문서화만.
- 관리자 차트는 데이터 0건이면 `st.info("기간 안에 질문이 없습니다")`.

## 6. 테스트
- 단위: 출처 카드 문자열 생성(번호·링크), 예시 질문 상수, `daily`/`search` SQL(통합, `ragdb_test`), 인용 지시가 두 프롬프트에 있음.
- AppTest: 후보 칩이 status 안에 그려짐(가짜 후보), `크게 보기` 버튼 존재·클릭 시 예외 없음, 다시 생성 클릭이 같은 질문으로 `hybrid_search` 를 다시 호출, 새 대화/전환 시 messages 가 바뀜, 관리자 검색 입력이 `search` 를 호출.

## 7. 범위 밖
- 프론트엔드 교체, 모바일 전용 레이아웃, 답변 복사 버튼(브라우저 선택 복사로 충분), 대화 영구 저장(로그인 필요), 스트리밍 중 인용 하이라이트.
